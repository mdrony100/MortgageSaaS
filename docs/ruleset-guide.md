# Versioned Phase 2 rules

`bank_rules` is append-only, scoped to an organization, unique by name/version. File access + reviewer role is needed to read/select; only organization Owner/Admin can approve a version, with an actual `approval_reference`. A share never grants reviewer rights. Examples are restricted to fictional development/testing files; no production example is seeded.

Required settings: personal/business applicability, eligible categories, `expense_treatment` (`none` or `remaining_percent`), ownership requirement/fixed ownership if applicable, remaining-income percentage if applicable, HALF_UP display rounding, required evidence, whether explicitly provisional observed-only calculations are permitted, external-integrity and open-finding finalization gates. Reconciliation tolerance (minor USD units) and rationale are configurable on the version; the technical default is one cent for extraction/statement rounding, not a lender income rule. Optional NSF event/liquidity/repeated-credit/cash/circular-window thresholds generate review observations only. Draft thresholds are labeled examples, never approved.

Transaction category and eligibility are distinct. Suggestions remain immutable. A reviewer can classify and explicitly include/exclude with a versioned reason; Other needs notes. Extraction corrections append their original source values plus corrected values and require explanatory notes. Account identity/designation must be confirmed separately; a masked suffix is only a candidate identity. Relationship evidence is explicitly verified in the same file/run. Transfer allocations are confirmed/rejected separately, cannot exceed either side and become untrusted if relationship/identity verification is revoked.

Calculation inputs select explicit accounts, all 12 or 24 target months, ownership and expense treatment. Missing essential rules/inputs withhold the figure. Draft rules and incomplete evidence can only produce a marked provisional result where the selected profile permits it, with explicit observed-only assumptions and the full selected denominator. Overlapping/duplicate coverage and unresolved selected-account transfer candidates withhold income to avoid double counting. Never divide by just available months, silently zero-fill unknown deposits, convert currencies, import business receipts into personal income or apply a universal personal/business expense formula.

The development business example 240,000 deposits − 40,000 exclusions = 200,000 eligible ×100% ownership ×50% remaining /12 = 8,333.33 USD is an example, NOT lender policy. The actual lender’s expense conventions, ownership/evidence requirements, NSF counting/thresholds and finalization gates must be supplied and approved.

Financial-input confirmation is itself an append-only `calculation_inputs` review with actor, exact choices, standardized reason/version and source notes. Original profile values remain intact when an authorized reviewer supplies an explicit input exception; the snapshot/report shows both policy and effective inputs and all applied review IDs. Repeated identical confirmation is idempotent. Subsequent classification-only reviews do not erase earlier financial corrections. Identity corrections/canonical same-run account assignment require source notes and fresh identity verification; transaction corrections invalidate prior daily-reconstruction attestation.

NSF algorithms are `reference_per_day` or `transaction_row`; free-text convention notes do not change the algorithm. Fees never add an event. Negative account-days require reviewer-attested complete source ledger plus exact-cent reconciliation, stricter than general review tolerance. Selected-account/selected-period NSF totals are separate from supporting-account coverage. Unsupported currencies are flagged, never combined as USD. Income-category decisions always require review before a final figure.
